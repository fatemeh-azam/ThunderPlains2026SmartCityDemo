Smart-City RF Monitoring Platform

Oklahoma Cyber Innovation Institute, 2024 to present

A real-time platform that collects telemetry from about seven ESP32 sensor nodes spread across several buildings, covering four RF bands: Wi-Fi, 433 MHz, GPS L1/L5, and LoRaWAN. Readings stream to a live dashboard. I built it end to end, from the C++ firmware on the sensors to the backend and the React front end.

{%- if site.images.smart_city_dashboard != "" %} {%- endif %}
  • MQTT ingestion with metric normalization across devices that each report differently; REST API, with Socket.io pushing updates to the dashboard.
  • Detection and classification of RF disruption.
  • Drone telemetry integration with ROS 2 output and MCAP recording, plus an MJPEG video proxy and PCM audio over WebSocket.

At ThunderPlains 2026, audience phones joined the testbed's MQTT bus live, through a QR code and a relay hosted on Render. Developers in the room wrote scripts to flood it with junk data. It stayed up.

Built with React, Node.js, Socket.io, MQTT, SQLite, C++ on ESP32, ROS 2

Reel Smart

Personal project, 2026

A local-LLM pipeline that generates, scores, and evolves phishing-awareness training messages. Nothing leaves the system until a person has reviewed and approved it.

  • The detector, not the model, writes the clue tags. It is calibrated against human-labeled data to about 82% agreement.
  • A red-team suite mapped to the OWASP Top 10 for LLM Applications and the OWASP Agentic Top 10. Prompt injection, poisoned-feed, secret-leakage, and misuse cases are all blocked with defenses on.
  • A live threat-intelligence feed from the FBI's IC3, behind layered defenses: a source allowlist, headline sanitization, and passing the model labels rather than raw text.

Built with Python, Ollama, Streamlit, SQLite

Micro-UAV Command-Stack Security

Oklahoma Cyber Innovation Institute, research

How command authority gets contested on small drones. On a Crazyflie testbed we characterized a class of command-authority vulnerabilities, then built a Random Forest detector that flags hijacks from flight telemetry.

Hijack detection results
MethodF1False-positive rate
Random Forest on telemetry0.9061.18%
Rule-based baseline–3.55%

In progress: multi-drone swarms

The next phase extends detection to swarm delivery missions and tests it on drones, routes, and drone pairings the model has never seen, using leave-one-drone-out and leave-one-mission-out validation. Trial data showed that an intruding radio is detectable seconds before the flight path changes, which led to a two-signal design: an early link-quality signal, confirmed by a trajectory-residual signal once the flight starts to deviate.

Built with Python, scikit-learn, XGBoost, PyTorch, Optuna, MLflow, ROS 2 with MCAP recording, and a Rust detection node running ONNX Runtime

Testbed software

The flight and monitoring code the experiments run on, published on its own, separate from the research tooling.

  • Delivery mission runner. Flies several Crazyflies in parallel on grid-aligned delivery routes, with a descent at each drop-off, battery checks before every leg, and telemetry logged without stalling the radio link.
  • Trajectory planner. Turns each route into a smooth 7th-order polynomial trajectory that the drone flies onboard, rounding corners and drop-offs without stopping, which cuts a mission from about 2 min 45 s to about 1 min 15 s.
  • Battery monitor. A small library on the drone's power telemetry that decides whether to keep flying, return to base, or land, and estimates remaining flight time from a recorded discharge.
  • Rule-based flight monitor. Flags drones that leave their route or stop sending telemetry, records each outage, and shows a live map with an event log. Its fixed thresholds make a simple baseline to compare learned detectors against.
